# 提交信息约定与原子提交示例（references）

> 本文件由 dream-git 按需加载。给出提交信息模板、原子提交示例与常见反模式。

## 1. 提交信息模板

```
<块号>: <意图> - <摘要>

[可选：根因/背景说明]
```

| 字段 | 说明 | 示例 |
|---|---|---|
| 块号 | tasks.md 中的块编号（无提案小任务可用简短主题词） | `001块2`、`login-fix` |
| 意图 | 动词短语：实现/修复/重构/补测/样式 | `实现`、`修复`、`重构`、`补测试` |
| 摘要 | 一句话说明改了什么、为什么 | `校验密码并签发会话` |

完整示例：
```
001块2: 实现登录接口 - 校验密码哈希并签发会话 Cookie

- 新增 POST /api/login（限流 + 错误码）
- 密码校验提取为 validateCredentials()（复用）
- 覆盖测试：成功/密码错误/限流 3 例
```

根因修复类示例：
```
login-fix: 修复偶发 500 - 统一用户行锁与会话表锁顺序

根因：两处加锁顺序不一致导致死锁（复现：并发 10 次登录）
回归：并发登录用例已加入测试集
```

## 2. 原子提交示例

❌ 非原子（一个提交混入多个逻辑块 + 无关改动）：
```
feat: 登录功能 + 顺带改了首页样式 + 删了无用依赖
```

✅ 原子（一提交一意图，可单独回滚）：
```
001块1: 实现用户数据模型 - User 表与密码哈希工具
001块2: 实现登录接口 - 校验密码并签发会话
001块3: 实现登录页面 - 表单与错误提示
```

> 回滚场景：`001块2` 出问题，`git revert` 该提交即可，不影响块 1/块 3。

## 3. 常见反模式

| 反模式 | 表现 | 正确做法 |
|---|---|---|
| 巨无霸提交 | 一次提交 50 个文件多个功能 | 拆成多个原子提交 |
| 验证前提交 | 测试红的代码也提交 | 块级验证通过才提交 |
| 混入无关改动 | 提交里夹带格式化/调试代码 | 无关改动单独提交或丢弃 |
| 无信息提交 | `update`、`fix`、`wip` | 按模板写块号+意图+摘要 |
| 提交后才发现漏文件 | 功能依赖的文件没提交 | 提交前 `git status` 核对完整 |
| 把密钥/生成物提交 | .env、dist、node_modules 入仓 | 遵守项目 .gitignore |

## 4. 分支纪律要点

- **遵循 CLAUDE.md 约定**：项目用 trunk-based 就小步直推；用 feature branch 就先建分支；
- Dreamskills 本身不规定分支模型，只要求：**提交纪律一致、块↔提交可追溯**；
- 有 PR 流程时：提交信息即 PR 描述素材（块号 + 摘要直接复用）。

## 5. 提交前快速核对

```
□ 本块验证通过（测试/构建/冒烟）
□ git status 仅含本块文件
□ 提交信息含块号 + 意图 + 摘要
□ 无密钥/生成物/调试残留
□ 提交后可单独回滚（粒度检查）
```
