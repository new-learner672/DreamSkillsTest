# 二分定位操作手册（references）

> 本文件由 dream-debug 按需加载。把"二分缩小范围"变成可执行步骤，按问题类型分四类。

## 0. 通用二分流程

1. 定义**可观测信号**（报错？白屏？数据错？性能差？）——没有可判定的信号无法二分；
2. 划分**两半**：沿代码路径/调用链/数据流找中点，做一次实验（打日志/断点/临时改值）；
3. 根据实验结果**保留有问题的一半**，丢弃另一半；
4. 重复直到收敛到最小可疑点（函数/行/条件）；
5. 验证收敛点是否为根因（修改后问题消失）。

> 信号必须稳定：每次实验前先确认问题仍在（防止"问题其实好了"误判）。

## 1. 前端类问题

- **白屏/渲染错误**：先看控制台报错 → 二分组件树（注释掉一半组件看是否恢复）→ 定位到具体组件/状态；
- **交互失效**：检查事件绑定 → 数据流（props/state）→ API 返回；二分：先 mock 数据排除后端；
- **样式异常**：检查 CSS 作用域/优先级 → 浏览器 DevTools 定位元素 → 二分样式来源（哪个文件/类）；
- **跨端差异**（浏览器 A 好 B 坏）：二分到特性差异（flex/grid/兼容 API），用 caniuse 验证。

常用工具：DevTools（Elements/Console/Network）、React DevTools、Playwright 最小复现页。

## 2. 后端类问题

- **接口报错**：复现请求 → 二分调用链（路由→中间件→控制器→服务→数据层），逐层加日志；
- **数据错误**：二分数据来源（输入参数 → 缓存 → 数据库），对比期望值与实际值；
- **依赖服务问题**：mock 外部依赖排除；用健康检查确认 DB/缓存/第三方可用；
- **git bisect**：回归型 bug 用 `git bisect` 二分历史提交，定位引入点（已知好/坏提交各一个）。

常用工具：日志分级（入口/出口/异常）、接口测试（curl/测试框架）、`git bisect`、APM 追踪。

## 3. 环境类问题

- **本地好/部署坏**：二分环境差异（依赖版本、env 变量、配置、权限、Node 版本）；
- **机器 A 好/机器 B 坏**：对比环境（系统、时区、语言、路径、编码）；
- **构建产物与源码不符**：先清缓存/重建，二分构建配置（压缩、tree-shaking、polyfill）；
- **偶发/时序问题**：加日志记录完整时序，二分"先发生什么后发生什么"。

要点：环境问题优先**对比**（两台机器/两个环境 diff），而不是在单点瞎猜。

## 4. 并发类问题

- **数据竞争/竞态**：定位共享状态 → 二分并发窗口（哪个读写交错导致问题）；
- **死锁/卡死**：抓线程栈/堆栈快照，二分持锁顺序；
- **偶发失败**：增大并发/加延迟复现，二分到具体竞态路径；
- **异步顺序错乱**：检查 await/回调时序，二分"哪个 Promise 先完成导致状态错"。

要点：并发 bug 先用**确定性复现**（固定线程数/固定延迟），能稳定复现后再二分。

## 5. 二分失败时的兜底

- 收敛点不是根因（改了问题仍在）→ 回到二分，检查是否**误判信号**；
- 无法二分（依赖太深/无从下手）→ 写最小复现程序，把问题从项目中剥离出来；
- 时间预算超限 → 记录已排查范围，向用户汇报并暂停（不无限深挖）。

## 6. 根因验证模板

```markdown
- 现象：登录接口偶发 500
- 最小复现：并发 10 次同账号登录
- 二分过程：接口层无异常 → 数据层偶发死锁 → 锁顺序（用户行锁 + 会话表锁）
- 根因：两处加锁顺序不一致
- 验证：统一锁顺序后并发 100 次无失败
- 回归测试：并发登录用例加入测试集
```
