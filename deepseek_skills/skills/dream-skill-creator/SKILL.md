# 元技能：创建与改进技能（dream-skill-creator）

> 定位：Dreamskills 的自我进化入口。踩坑经验与团队规范 → 可复用的新技能。
> 吸收思想：anthropics 的 skill-creator（官方格式与规范）+ superpowers 的 writing-skills / improving-skills（经验固化与持续改进）。

## 何时使用（触发条件）

- 同一类踩坑经验出现 ≥2 次（值得固化）；
- 团队规范需要可复用（编码规范、流程要求、常用命令）；
- 现有技能失效 / 过长 / 触发不准时（改进）。

不适用：一次性经验（不值得固化）；只改一个词句的小调整（直接编辑，不必走本流程）。

## 核心原则

1. **技能即文件**：遵循官方 Agent Skills 格式（SKILL.md + references/），可版本化、可共享。
2. **触发优先**：description 第三人称 + 触发词（引号括起），让 agent 能自动识别何时调用。
3. **渐进式披露**：正文 ≤150 行，细节/清单放 references/，按需加载。
4. **统一骨架**：与 Dreamskills 其他技能一致（定位/吸收思想/触发/原则/流程/验收/衔接/进阶）。
5. **持续进化**：创建后必须试用、按反馈改进（improving-skills 思想）。

## 工作流程

### 步骤 1：明确触发场景（创建时）

- 用户会在什么情况下调用？一句话说清"何时使用/何时不适用"；
- 提炼该经验的核心原则（3~5 条可执行规则）。

### 步骤 2：写 description

- 第三人称；≤1024 字符；含触发场景关键词并用引号括起（如"审查这次变更"、"浏览器验证"）。

### 步骤 3：写正文骨架

- 按统一骨架七段：标题 → 定位 → 吸收思想 → 何时使用 → 核心原则 → 工作流程 → 验收标准 → 衔接 → 进阶资料；
- 工作流程步骤化：每步含输入/动作/产物。

### 步骤 4：细节下沉

- 清单、模板、数据（阈值/片段）放入 references/；正文只留指引。

### 步骤 5：自检

- 按 references/skill-format-guide.md 的自检清单逐项核对（frontmatter、命名、骨架、行数、description）。

### 步骤 6：试用与改进（不可跳过）

- 实际触发一次新技能（或对现有技能做一次诊断：太长？触发不准？缺产物？缺验收？）；
- 按试用反馈修正；在 .dreamspec/SKILLS.md 登记启用。

## 验收标准

- [ ] frontmatter 仅 name + description，name 与目录名一致
- [ ] description 第三人称、含引号触发词、≤1024 字符
- [ ] 正文骨架七段齐全、≤150 行
- [ ] 细节在 references/，正文无大段清单
- [ ] 已试用并记录改进反馈；已在 SKILLS.md 登记

## 与其他技能的衔接

- 上游：任意踩坑现场（dream-debug 的根因报告、dream-review 的重复建议、团队规范）
- 下游：被创建/改进的技能本身（可被流水线中其他技能引用）
- 治理：新技能需在 .dreamspec/SKILLS.md 登记启用；格式与官方 Agent Skills 规范一致可共享

## 进阶资料
