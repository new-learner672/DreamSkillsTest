# SKILL.md 格式指南与自检清单（dream-skill-creator 的 references）

> 依据：官方 Agent Skills 规范（SKILL.md 简洁第一原则）+ Dreamskills 统一骨架。

## 一、官方 SKILL.md 格式要点

- 技能 = 一个目录：`SKILL.md` + 可选 `references/`（细节按需加载）+ 可选 `scripts/`；
- `SKILL.md` 首部为 frontmatter（YAML）：`name`（与目录名一致）+ `description`；
- **渐进式披露**：SKILL.md 保持简洁，细节放 references/，按需加载（控制 token）；
- 技能文件为纯 Markdown，平台中立（Claude Code / Codex / Cursor 等兼容）。

## 二、Dreamskills 统一骨架模板

```markdown
---
name: <技能名（与目录名一致）>
description: <第三人称描述触发场景与职责，≤1024 字符，触发关键词用引号括起>
---

# <中文名>（<技能名>）

> 定位：<一句话：在流水线中的位置与职责>
> 吸收思想：<上游思想 + 对上游弱点的改进>

## 何时使用（触发条件）

- <触发场景 1>；
- <触发场景 2>。

不适用：<明确不适用场景>。

## 核心原则

1. <原则 1>
2. <原则 2>

## 工作流程

### 步骤 1：<步骤名>

- <输入 / 动作 / 产物>

## 验收标准

- [ ] <可勾选验收项>

## 与其他技能的衔接

- 上游：<技能>（<关系>）
- 下游：<技能>（<关系>）
- 强度模式：<rigorous / balanced / light 三档裁剪说明>

## 进阶资料

- references/<文件名>：<内容与何时加载>
```

## 三、自检清单（创建/改进后逐项核对）

- [ ] frontmatter 仅含 name + description（无多余字段）
- [ ] name 与目录名完全一致
- [ ] description 为第三人称，≤1024 字符，含引号括起的触发关键词
- [ ] 正文标题为「# 中文名（dream-xxx）」
- [ ] 含「> 定位：」与「> 吸收思想：」两行引言
- [ ] 骨架段齐全：「何时使用（含不适用）」「核心原则」「工作流程」「验收标准」「与其他技能的衔接」「进阶资料」
- [ ] 正文 ≤150 行；大段清单/模板/数据已移入 references/
- [ ] 工作流程步骤含输入/动作/产物
- [ ] 验收标准为可勾选「- [ ]」形式
- [ ] 衔接写明上游/下游且与流水线一致；强度模式标注三档裁剪
- [ ] 中文通顺、术语一致（验证门、提案、GWT、强度模式等）
- [ ] 已试用一次并记录反馈；新技能已在 .dreamspec/SKILLS.md 登记

## 四、改进现有技能的四类诊断

| 症状 | 诊断 | 对策 |
|---|---|---|
| 正文太长、agent 不读 | 违反渐进式披露 | 细节下沉 references/，正文瘦身 ≤150 行 |
| 该触发时不触发 | description 缺触发词 / 触发场景不清 | 重写 description，补引号触发词 |
| 做了但没产物 | 工作流程缺"产物" | 每步骤明确产物并写入验收标准 |
| 做完没法验收 | 缺验收标准 / 验收不可勾选 | 补「- [ ]」验收项，可观测化 |
