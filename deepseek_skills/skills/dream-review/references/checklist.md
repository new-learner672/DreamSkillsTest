# 代码审查完整清单（dream-review 的 references）

> 使用方式：审查时逐项勾选；每一项记录 通过 / 发现（文件:行号 + 问题描述）。
> 问题分级：🔴 阻断（必须修复，否则不进入 dream-verify）/ 🟡 建议（记录即可，不阻塞）。

## 维度 1：正确性（Correctness）

- [ ] 逻辑符合 spec-delta 的 GWT：逐条 GWT 有对应实现且行为可观测（例：GWT"当输入正确密码，那么登录成功"→ 有对应分支与跳转）
- [ ] 边界条件处理：空值、越界、重复提交、并发（例：用户名为空时给出校验提示而非 500）
- [ ] 异常路径：try/catch 覆盖，错误信息不泄漏内部细节
- [ ] 状态流转正确：页面/会话/流程状态机无死路（例：登录失败后停留当前页并提示）
- [ ] 数据一致性：写入前校验、事务/原子性（例：转账扣款与入账同事务）

## 维度 2：安全（Security）

- [ ] 输入校验：所有外部输入经过校验/清洗（防注入）
- [ ] 输出编码：动态内容渲染前转义（防 XSS）
- [ ] 权限检查：每个受保护操作都有授权校验（防越权）
- [ ] 敏感信息：无密钥/令牌/个人数据硬编码或写入日志
- [ ] 认证与会话：令牌过期、会话失效逻辑正确

> 详细核对见 dream-security-check 的 references/owasp-top10.md；本维度只做初筛，深检交给 dream-security-check。

## 维度 3：可维护性（Maintainability）

- [ ] 命名清晰：变量/函数/组件名表达意图
- [ ] 函数单一职责：无超长函数（>50 行应拆分）
- [ ] 重复代码：同类逻辑已抽取或可接受（记录原因）
- [ ] 注释：复杂逻辑有"为什么"注释；注释与代码同步（不撒谎）
- [ ] 依赖：新增依赖有理由，无重复/废弃依赖

## 维度 4：性能（Performance）

- [ ] 无明显 N+1 查询 / 循环内请求
- [ ] 大列表有分页/虚拟化，图片有尺寸与懒加载
- [ ] 无阻塞主线程的重计算（长任务）
- [ ] 资源体积：无超大 bundle / 未压缩图片

> 详细度量见 dream-perf-audit；本维度只做静态初筛。

## 维度 5：与 spec 一致性（Spec Conformance）

- [ ] spec-delta 每条 GWT 有实现落点
- [ ] 非目标（proposal.md 声明不做的事）没有被实现
- [ ] 行为变更与既有 specs/ 无冲突（有冲突应回 dream-spec-propose 更新提案）

## 审查报告模板（写入 changes/<id>/review.md）

```markdown
# 审查报告 <id>
- 审查对象：<commit / diff 范围>
- 审查时间：<日期>

## 阻断项（必须修复）
1. 🔴 <文件:行号> <问题> <建议修复>

## 建议项（记录即可）
1. 🟡 <文件:行号> <问题>

## 结论
- 阻断项清零：是 / 否（豁免：<原因>）
- 是否允许进入 dream-verify：是 / 否
```
