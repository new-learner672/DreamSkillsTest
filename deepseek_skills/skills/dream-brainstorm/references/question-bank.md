# 追问问题库（references）

> 本文件由 dream-brainstorm 按需加载。按五个维度组织问题，每轮只挑最关键 1~3 个问，避免"问卷轰炸"。

## 1. 边界（做什么 / 不做什么）

- 这个功能的核心场景是什么？用户/角色是谁？
- 哪些场景**明确不做**（本期非目标）？
- 与现有功能/模块的边界在哪里？（是否有重叠、是否复用）
- 输入/输出的范围是什么？（数据量级、文件类型、平台）
- 是否影响存量行为？影响面多大？

## 2. 规则（行为如何定义）

- 关键业务规则是什么？（如密码强度、价格计算、权限判定）
- 是否存在隐含默认值/超时/上限？（会话时长、重试次数、文件大小）
- 规则是否可验证？能否写成 Given-When-Then？
- 规则冲突时以哪个为准？（如"管理员可覆盖"）
- 是否需要配置项/环境变量？（否则写死，明确默认值）

## 3. 异常（出错怎么办）

- 失败场景有哪些？（网络错误、输入非法、依赖不可用）
- 错误如何呈现？（提示文案、错误码、日志级别）
- 是否有重试/回退/补偿机制？回退到什么状态？
- 部分成功怎么办？（批量操作中途失败）
- 极端输入会怎样？（空值、超长、并发）

## 4. 优先级（先做什么）

- 哪些是必须（MVP）？哪些可以后置（P1/P2）？
- 如果时间不够，砍掉哪部分可接受？
- 性能/体验的优先级高于还是低于功能完整性？
- 是否存在依赖前置任务？（其他功能、外部系统）

## 5. 非目标（明确排除，防范围蔓延）

- 本期明确不做什么？（列出具体项）
- 哪些"顺便"想法要拆成新提案？（避免提案混杂）
- 不支持的平台/浏览器/环境有哪些？

## 提问技巧

- 每轮聚焦：先问最可能改变方案走向的问题（通常先问边界与关键规则）；
- 用选择题代替开放题：`密码强度：A 仅长度 / B 长度+字符类型 / C 长度+字符+防暴力破解？`
- 标注推断：`我推断 X（因为 Y），对吗？`——避免把猜测当用户决策；
- 及时喊停：问题足以支撑提案/计划即停止，剩余细节留到实施时按需问（平衡"问清楚"与"不过度"）。
