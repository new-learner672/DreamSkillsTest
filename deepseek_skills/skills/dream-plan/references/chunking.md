# 分块策略详解与示例（references）

> 本文件由 dream-plan 按需加载。回答"怎么把需求切成好块"：粒度、边界、顺序、验收点。

## 1. 为什么分块

- **对抗上下文漂移**：一次只加载当前块，长任务不依赖上下文窗口（superpowers 的工件即记忆 + 渐进式披露）；
- **可验证**：每块有验收点，做完即验证，问题早暴露；
- **可回滚**：块是原子提交的最小单位（dream-git），失败只回滚一块。

## 2. 分块边界判定（怎么切）

按以下维度切块，优先满足第一个命中项：

| 维度 | 切分信号 | 示例 |
|---|---|---|
| 依赖 | 有先后依赖关系的先切出来 | 数据模型 → 接口 → UI |
| 验收 | 能独立验证的一坨功能算一块 | "登录接口 + 测试"一块；"登录页 UI"一块 |
| 类型 | 逻辑 / UI / 数据 / 配置分离 | 逻辑块挂 dream-tdd，UI 块挂 dream-design-system |
| 风险 | 高风险块单独切、单独验证 | "支付回调幂等"独立一块 |
| 大小 | 超过半天工作量的继续切 | "用户管理 CRUD"切为"列表/详情/新增/编辑" |

## 3. 粒度示例（用户登录功能）

❌ 过粗（一块做完、无法验证）：
```
块 1：实现登录功能（- 验收点：能用）
```

✅ 合适（每块可独立验证、可独立回滚）：
```
块 1：用户数据模型与密码哈希（数据）
  - [ ] 建 User 表 + 密码哈希工具
  - 验收点：哈希工具单测通过；表结构迁移可回滚

块 2：登录接口（逻辑）
  - [ ] POST /api/login：校验密码、签发会话、限流
  - 验收点：接口测试 3 例通过（成功/密码错/限流）

块 3：登录页面与错误提示（UI）
  - [ ] 登录表单 + 错误提示 + 跳转首页
  - 验收点：浏览器 E2E 登录成功/失败通过；反 slop 自检通过
```

## 4. 依赖排序规则

1. 被依赖的块排前面（数据 → 接口 → UI）；
2. 无依赖的可并行块标注"可并行"（供 dream-execute 委派模式参考）；
3. 风险块尽量靠前（早验证早止损）；
4. 重构/迁移类任务：先加"行为快照测试"块，再动实现块。

## 5. 验收点写法

- 必须**可验证**：`接口测试 3 例通过`、`E2E 登录成功/失败通过`、`构建无警告`；
- 禁止模糊：`功能能用`、`体验良好`；
- 验收点与 spec-delta 的 GWT 对应，dream-verify 可据此取证。

## 6. 强度模式下的粒度

| 模式 | 粒度 | tasks.md 形态 |
|---|---|---|
| rigorous | 每块含具体步骤、涉及文件、风险点 | 详细计划，块内分步 |
| balanced | 每块任务 + 验收点 | 常规计划（默认） |
| light | 一句话任务清单 | `- 做登录（接口+页面+测试）`，可跳过确认 |
