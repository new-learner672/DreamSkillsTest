# AI 生成代码特有失效模式排查表（Guard 第二遍审查用）

> 通用 lint 覆盖不了 AI 的典型错误。对本次变更 diff 逐项排查，发现问题给出文件:行号证据。

## 1. 幻觉类（不存在的东西）

- [ ] 幻觉 API：调用的库函数/参数名不存在 → 逐条在真实文档/类型定义中核对签名
- [ ] 幻觉配置：写了不存在的配置项（如不存在的 tsconfig 字段、环境变量）
- [ ] 幻觉数据：mock 数据引用了接口未返回的字段

## 2. 假成功类（永远通过的代码）

- [ ] 硬编码返回值：函数写死 true/成功，绕过了真实逻辑
- [ ] 吞异常：`catch {}` 或 `except: pass` 后继续执行
- [ ] 断言被降级：把 `assertEqual` 改成 `assertTrue(x is not None)`
- [ ] 测试跳过：`skip`/`xfail`/注释掉断言
- [ ] 时序竞态：异步等待缺失导致测试碰巧通过

## 3. 复制粘贴类（测试失去验证力）

- [ ] 测试复读实现：测试代码是实现的复制（同样的公式/逻辑）
- [ ] 参数化退化：应该参数化的 10 个用例被复制粘贴 10 份
- [ ] 死测试：测试永远通过、断言不到实质行为、从未见过红色

## 4. 结构类

- [ ] 过早抽象：为一次性需求建了 3 层接口/工厂
- [ ] 职责混杂：一个函数既查数据又渲染又存状态
- [ ] 循环依赖：模块 A→B→A
- [ ] 注释污染：注释与代码矛盾、翻译式注释（`// 设置x` 配 `setX()`）、过期 TODO

## 5. 安全类（OWASP 高频）

- [ ] SQL 注入：字符串拼接 SQL（必须参数化）
- [ ] XSS：用户输入未转义直接 innerHTML/渲染
- [ ] 密钥泄露：API key/密码写进代码、提交进 state 文件、打进前端包
- [ ] 越权：接口未校验资源归属（用户 A 能读用户 B 的数据）
- [ ] SSRF：用户可控 URL 直接由服务端请求

## 6. 边界类

- [ ] 空值：可选字段未判空直接访问
- [ ] 并发：共享状态无锁/原子性考虑
- [ ] 超大数据：无分页/无上限的列表加载
- [ ] 错误路径：只测 happy path，异常分支未处理

## 排查方法

对每条可疑代码：先假设它是错的 → 找反证（运行、读文档、写最小验证）→ 确认后记录证据。
